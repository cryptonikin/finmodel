# CLAUDE.md — правила для сессий Claude Code в репозитории finmodel

## Среда
- Работаешь в изолированном контейнере. `/workspace` = `D:\finmodel\code` = git-репозиторий
  `github.com/cryptonikin/finmodel` (приватный). Папки `secrets` и `data` владельца тебе не видны и не нужны.
- **Не делай `git push`** и не настраивай доступ к GitHub. Только локальные коммиты (автор
  `Claude Code (finmodel) <claude-code@localhost>`, ветка `main`). Push делает владелец с Windows после
  `scripts\check-secrets.ps1`.
- Язык общения, комментариев, отчётов и сообщений коммитов — **русский**. Код и имена — английский.

## Запреты
- **Никаких секретов** в файлах: токенов, ключей, ID таблиц, email, номеров счетов. Только шаблоны (`.env.example`).
- **Никаких реальных данных портфеля** (сделки, суммы, позиции). Тесты — на выдуманных данных, без сети (fakes).
- Не обращайся к Google, MOEX, Т-Банку из контейнера Claude Code — всё сетевое за интерфейсами.
- Без `rm -rf` за пределами `.venv/`, `build/`, кэшей. Проверку TLS никогда не отключать.

## Как работать
- Сначала короткий план, потом код. Маленькие шаги, `pytest` и `ruff check .` до коммита.
- Версии зависимостей — точные (`==`), проверенные установкой.
- В конце этапа — `REPORT_Fn.md` и коммит с сообщением из ТЗ.
- ТЗ этапов — `docs/tasks/TASK_Fn_vX.Y.md`. Версия — в имени файла; новая версия = новый файл, старый удалить.

## Решения проекта (не менять без владельца)
| Тема | Решение |
|---|---|
| Источник правды | Google Таблицы «Расчет инвестиций» и «Бюджет и инвестиции - ai»; контракт — `docs/SHEETS_INTERFACE_v*.md` (при расхождении с ТЗ верен он) |
| БД | SQLite сейчас, Postgres на VPS → весь SQL только в `app/db.py`, переносимый |
| Расписание | планировщик в контейнере + догон пропущенного слота **один раз** при старте |
| Секреты | файлы вне репо → Docker secrets (`/run/secrets/...`); ID таблиц — env-файл вне репо |
| Колонки | **только по заголовку** (точно, затем по началу; неоднозначность = ошибка; дубли — `occurrence`), никогда по букве |
| Запись в таблицы | только пакетом `values.batchUpdate` по точным адресам, бэкап перед записью, dry-run по умолчанию; новые листы — только с согласия владельца. В Ф0 записи нет |
| Писатели | одна колонка — один писатель; ручные колонки и формулы не трогать |
| Рост таблиц | данные/история/логи — в SQLite и файлах; строки и колонки «про запас» не добавлять; нет места — стоп и отчёт |
| Очистка | `config/retention.yaml`; удалять только внутри `/data` |
| Настройки | лист «Docker: настройки» — только 4 параметра владельца; техническое — `config/*.yaml` |
| smart-lab | в Docker не используем |
| Telegram | позже, только уведомления, без входящих команд и без сумм портфеля |

## Структура
`app/` — код (`__main__.py` CLI, `settings.py`, `user_settings.py`, `logging_setup.py`, `db.py`, `context.py`,
`sheets/{client,headers,contract}.py`, `jobs/{check,cleanup}.py`, `scheduler.py`); `config/` — YAML; `tests/` — pytest;
`scripts/` — хуки и скрипты владельца; `docs/` — ТЗ и контракты.
