## 0. Как работать (обязательно)

1. Ты внутри изолированного контейнера. `/workspace` = `D:\finmodel\code` на Windows = будущий git-репозиторий
   `github.com/cryptonikin/finmodel` (приватный). Другие папки владельца (`secrets`, `data`) тебе **не видны и не нужны**.
2. Язык общения, комментариев, отчётов и сообщений коммитов — **русский**. Код, имена — английский.
3. **Не делай `git push`** и не настраивай доступ к GitHub. Только локальные коммиты. Push делает владелец с Windows.
4. **Никаких секретов** в файлах: ни токенов, ни ключей, ни ID таблиц, ни email. Только шаблоны (`.example`).
5. **Никаких реальных данных портфеля** (сделки, суммы, позиции). Тесты — на выдуманных данных.
6. **Не обращайся к Google, MOEX, Т-Банку** в Ф0 из контейнера Claude Code — ключей здесь нет. Всё сетевое — за интерфейсами, тесты — с подделками (fakes).
7. Версии зависимостей — **точные** (`==`), выбери актуальные стабильные и проверь установкой.
8. Сначала план (кратко, в чат), потом код. Маленькие шаги, тесты до коммита. Без `rm -rf` за пределами `/workspace/.venv`, `build/`, кэшей.
9. В конце — `REPORT_F0.md` (§9) и один локальный коммит «Ф0: каркас».

## 1. Контекст проекта (кратко)

Финмодель брата (налоговый резидент РФ, брокер Т-Банк). Источник правды — **Google Таблицы**:
«Расчет инвестиций» (основная модель) и «Бюджет и инвестиции - ai». Сейчас логика — в Apps Script таблицы
(`moex_sync` 1.47, `autoideas` 1.18): MOEX ISS, ЦБ, smart-lab, Финам → ТА/ФА/скоринг → листы.
Этот репозиторий — Python-сервис в Docker (сначала ноутбук владельца, потом VPS), который **параллельно** с Apps Script:
- Ф1: импорт операций Т-Банка (T-Invest API, read-only токен) → промежуточный лист → «Журнал»;
- Ф2: перенос расчётов (MOEX/ЦБ → кэш → лист «Сверка» → смена писателя по колонке);
- Ф3: Telegram — только уведомления;
- Ф4: перенос на VPS.

**Ф0 (эта задача):** каркас + проверка таблиц **только на чтение** (`finmodel check`).

### Принятые решения (не менять без владельца)
| Тема | Решение |
|---|---|
| БД | SQLite сейчас, Postgres на VPS → доступ к БД только через слой `app/db.py` (без SQL-диалектных трюков) |
| Расписание | планировщик внутри контейнера + **догон** пропущенных задач при старте (ноутбук бывает выключен) |
| Секреты | файлы вне репозитория → Docker secrets (`/run/secrets/...`); ID таблиц — env-файл вне репо |
| Колонки таблиц | **только по заголовку** (точное совпадение, иначе по началу текста), никогда по букве |
| Запись в таблицы | только пакетом, бэкап (копия файла) перед первой записью, dry-run по умолчанию, новые листы — только с согласия владельца. **В Ф0 записи нет вообще** |
| Писатели | одна колонка — один писатель; Docker пишет в свои листы/колонки, ручные и формулы не трогает |
| smart-lab | в Docker не используем (остаётся в Apps Script) |
| Telegram | позже, только уведомления, без входящих команд, без сумм портфеля |

## 3. Docker

**Dockerfile:** `python:3.12-slim-bookworm` (точный тег), пользователь не root (uid 10001), `PYTHONDONTWRITEBYTECODE=1`,
`PYTHONUNBUFFERED=1`, зависимости из `requirements.txt` с `--no-cache-dir`, код в `/app`, `ENTRYPOINT ["python","-m","app"]`.
Без лишних системных пакетов. Готовность к будущему: место для корневого сертификата Минцифры
(`certs/` в репо пустая с README; копирование в `/usr/local/share/ca-certificates/` + `update-ca-certificates` — закомментировано до Ф1). Проверку TLS **никогда** не отключать.

**docker-compose.yml** — два сервиса на одном образе:
```yaml
services:
  app:                       # разовые команды: docker compose run --rm app check
    build: .
    env_file: ../secrets/finmodel.env
    secrets: [google_sa]
    volumes: ["../data:/data"]
    user: "10001:10001"
    read_only: true
    tmpfs: ["/tmp"]
    cap_drop: [ALL]
    security_opt: ["no-new-privileges:true"]
    mem_limit: 512m
    # портов НЕТ
  scheduler:                 # фоновый, включается позже: docker compose --profile scheduler up -d
    <то же самое>
    command: ["scheduler"]
    restart: unless-stopped
    profiles: ["scheduler"]
secrets:
  google_sa:
    file: ../secrets/google-sa.json
```
Пути `../secrets` и `../data` — относительно `D:\finmodel\code`. Проверь синтаксис `docker compose config` невозможен без Docker — проверь YAML парсером и опиши в отчёте.

## 4. Безопасность (проверяется в отчёте пунктами)

- `.gitignore`: `.env`, `.env.*` (кроме `.env.example`), `*.json` в корне и `secrets/`, `data/`, `*.db`, `reports/`, `logs/`, `.venv/`, кэши, `*.pem`, `*.key`, `*.p12`, `google-*.json`, `*credentials*`.
- `.dockerignore`: то же + `.git`, `tests`.
- **detect-secrets**: `.secrets.baseline`, git pre-commit hook (`scripts/install-hooks.sh`), установи его. Если на машине владельца (Windows) инструмента нет — хук выводит предупреждение и не блокирует (коммиты делает в основном Claude Code).
- `scripts/check-secrets.ps1`: `docker run --rm -v "${PWD}:/repo" zricethezav/gitleaks:<точная версия> detect --source=/repo --no-banner` (для владельца перед push).
- Логи: фильтр маскирует всё, похожее на токен/ключ (`t.` + длинная строка, `-----BEGIN`, `"private_key"`, длинные base64); значения секретов **никогда** не логируются, даже в ошибках (`settings` сообщает «файл секрета не найден: google_sa», не содержимое).
- Google: scope **только** `https://www.googleapis.com/auth/spreadsheets.readonly` в Ф0. Запись появится в Ф1 отдельным scope и флагом.
- Сеть: только исходящие запросы, таймауты на всё, ретраи с паузой.

## 6. Расписание `config/schedule.yaml` и догон

```yaml
timezone: Europe/Moscow
jobs:
  check: {at: ["07:30"], days: daily, catch_up: true}
```
`scheduler.py`: раз в минуту проверяет, какие запуски положены; последний успешный запуск — в SQLite `job_runs`
(`job, started_at, finished_at, status, message`). При старте: если последний положенный слот пропущен — выполнить **один раз**
(не по количеству пропусков). Одновременно одна задача (блокировка). Корректная остановка по SIGTERM.
Чистые функции расчёта «что положено» — тестируются отдельно с фиксированным временем.

## 7. Задача `check` (Ф0)

`python -m app check [--json]`:
1. Проверить наличие env-переменных и файла секрета (без печати значений).
2. Для каждой таблицы: открыть по ID (read-only), получить список листов.
3. Для каждого листа контракта: лист существует? для `header_row` — **одним batchGet** на таблицу прочитать строки заголовков;
   найти каждый `required`; собрать: найден / не найден / неоднозначен; список всех дублей в строке заголовков.
4. Итог: таблица в консоли + отчёт `/data/reports/check_YYYYMMDD_HHMM.md` (каталог создать).
5. Код выхода: 0 — всё найдено; 1 — есть пропуски/неоднозначности; 2 — нет доступа/секретов.
6. Ничего не записывать в таблицы. Минимум запросов к API (≤ 4 на запуск).

## 10. Добавлено в v1.1: настройки владельца и логи

### 10.1. Настройки из листа «Docker: настройки» (решение владельца 01.11.2026)
UI настроек для MVP — **лист в таблице «Расчет инвестиций»**. Docker его **только читает**. Сам лист создаст архитектор
после приёмки Ф0 (с бэкапом); в Ф0 листа может не быть — тогда берутся значения по умолчанию и в `check` предупреждение.

Формат листа (строка заголовков — 1, данные с 2-й):
| Параметр | Значение | Описание | Допустимые значения |
|---|---|---|---|
| `enabled.tinvest_import` | нет | импорт операций Т-Банка (Ф1) | да / нет |
| `tinvest.period_months` | 3 | период импорта по умолчанию | 1–3 |
| `write.dry_run` | да | режим «только показать» для записей | да / нет |
| `schedule.tinvest_import` | 21:30 | время импорта Т-Банка (МСК) | ЧЧ:ММ |

- `config/settings_defaults.yaml` — эти же ключи со значениями по умолчанию и правилами проверки (тип, диапазон, список).
- `user_settings.py`: читает лист по заголовкам (как §5, alias `docker_settings`, `header_row: 1`, ключ «Параметр»),
  проверяет каждое значение по правилам; неверное или неизвестное → значение по умолчанию + предупреждение (не падать).
  «да/нет» без учёта регистра; числа с десятичной запятой.
- **Секретов в листе быть не может**: если значение похоже на токен/ключ (правила маскировки §4) — игнорировать и предупредить.
- Технические настройки (пути, лимиты, таймауты) — не в листе, а в YAML в репозитории.
- Добавь лист в контракт `sheets_map.yaml` с флагом `optional: true`.
- Тесты: нормальный лист; нет листа; неверное значение; неизвестный ключ; «секрет» в значении.

### 10.2. Логи и журнал запусков (решение владельца 01.11.2026)
- **Технические логи** — файлы `/data/logs/finmodel.log`, ротация по суткам, хранение **30 дней**
  (`TimedRotatingFileHandler`, `backupCount=30`; см. §13), формат: время МСК · уровень · задача · run_id · сообщение.
  Плюс вывод в консоль (виден в `docker compose logs`). Маскировка секретов — в обоих.
- **Журнал запусков** — SQLite `job_runs`: `run_id, job, trigger (schedule|catch_up|manual), started_at, finished_at, status (ok|warn|error), summary, rows_read, rows_written`.
  Команда `python -m app runs [--last 20]` — печатает последние запуски.
- Хранение журнала запусков — 90 дней (см. §13).
- Отдельных просмотрщиков логов (Dozzle, Grafana) не ставить.
- В Ф0 **не делать**: аудит записей в таблицы, лист «Docker: журнал», письма об ошибках — это последующие этапы.

## 12. Добавлено в v1.3: таблицы не должны разрастаться (решение владельца 06.11.2026)

Правила для всего кода (сейчас и в Ф1+):
1. Данные, история, сырые операции, логи, журнал запусков — **в SQLite / файлах**, не в листах.
2. Код **не добавляет пустые строки и колонки «про запас»**. Новая строка — только под реальные новые данные и только в уже существующие пустые строки; нет места → стоп и отчёт, без вставки строк.
3. Новые листы — только с согласия владельца.

В `check` (Ф0) добавь **контроль размера**: для каждого листа контракта получить `gridProperties.rowCount/columnCount`
(уже приходят вместе со списком листов — без лишних запросов) и последнюю строку данных по ключевой колонке;
если пустой хвост > 300 строк или колонок больше, чем последняя непустая в строке заголовков + 5 —
**только предупреждение** в отчёте и логе (код выхода не меняется). Ничего не удалять: строки обрезает Apps Script (1.45+).

## 13. Добавлено в v1.4: очистка данных — Docker и БД не разрастаются (решение владельца 06.11.2026)

Принцип: **локально храним только то, что нужно для работы и дедупа**. Всё, что уже перенесено в Google Таблицы,
локально удаляется по сроку. Сроки — в `config/retention.yaml` (в репо), не в листе настроек.

### 13.1. Задача `cleanup` (ежедневно после импорта, 21:45 МСК, с догоном; и командой `python -m app cleanup [--dry-run]`)
| Что | Где | Срок по умолчанию | Правило |
|---|---|---|---|
| Технические логи | `/data/logs` | 30 дней | ротация + удаление старше срока |
| Журнал запусков `job_runs` | SQLite | 90 дней | удаление строк |
| Отчёты (`check_*`, `tinvest_*`) | `/data/reports` | 30 дней, не больше 100 файлов | старые удаляются первыми |
| Бэкапы листов (JSON) | `/data/backups` | последние 10 и не старше 30 дней | — |
| Операции брокера `tinvest_operations` | SQLite | окно загрузки + 14 дней (≈ 3,5 мес) | старше — удалить: записанные уже в «Журнале» (дедуп по «Источник: T-API op_id»), сопоставленные — найдутся снова |
| `journal_sync` | SQLite | как операции | вместе с операциями |
| Кэш инструментов | SQLite | не использовался 90 дней | удалить |
| Кэш котировок (Ф2) | SQLite | задаётся в Ф2 | — |

После удаления: если освобождено > 10% файла БД или раз в 30 дней — `VACUUM`.
Предупреждение в логе и отчёте `check`, если: БД > 200 МБ, `/data` > 1 ГБ, логи за сутки > 20 МБ.
Отчёт `cleanup`: сколько удалено по каждому пункту, размер БД до/после. Никогда не удалять ничего вне `/data`.

### 13.2. Docker (настроить в compose и README)
- Логи контейнеров: `logging: {driver: json-file, options: {max-size: "10m", max-file: "3"}}` для всех сервисов.
- `tmpfs: ["/tmp:size=64m"]`, корень контейнера только для чтения — внутри контейнера ничего не копится.
- Разовые команды — только `docker compose run --rm …` (контейнер удаляется после выполнения).
- Контейнер не имеет доступа к Docker на хосте (это правильно), поэтому очистку образов делает владелец скриптом
  `scripts/docker-cleanup.ps1` раз в месяц: `docker image prune -f` (только «висячие» образы после пересборки),
  `docker builder prune -f --filter "until=720h"`, вывод `docker system df` до/после. **Без** `-a` и **без** `--volumes`
  (иначе удалятся образ n8n и данные). Напоминание об этом — строкой в отчёте `check` раз в 30 дней.

### 13.3. Тесты
Очистка по срокам с фиксированным «сегодня»; лимит 100 отчётов; бэкапы «10 последних»; `--dry-run` ничего не удаляет;
операции внутри окна не удаляются; путь вне `/data` → отказ.
