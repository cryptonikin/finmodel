## 0. Цель и границы

Ежедневно и по команде загружать операции брокерского счёта Т-Банка за период (по умолчанию **3 мес**, параметр 1–3)
и добавлять в лист «Журнал» **только новые** операции, без дублей и без роста листа.

**Не входит в Ф1:** торговые операции и заявки (только чтение!), позиции/портфель (Ф1б), рыночные данные, Telegram.

| Решение владельца | Значение |
|---|---|
| Токен | **только чтение**, секрет Docker `tinvest_token` (`D:\finmodel\secrets\tinvest-token.txt`) |

| Запись | dry-run по умолчанию; запись — только флаг `--apply` **и** настройка `write.dry_run = нет` |

## 1. Зависимости и сертификат

1. SDK: пакет **`t-tech-investments`** с PyPI (официальный SDK T-Invest, gRPC). Перед использованием проверь, что пакет
   публикует Т-Банк (ссылки на `developer.tbank.ru` / репозиторий в метаданных пакета); укажи в отчёте версию и как проверил.
   Если пакет недоступен или не официальный — **остановись и спроси владельца** (альтернатива: gRPC-стабы из официальных proto).
2. Сертификат: «Russian Trusted Root CA» — скачать **только** с официального источника (Госуслуги / Минцифры),
   положить в `certs/`, в README записать источник и **SHA-256 отпечаток**; в Dockerfile — копирование в
   `/usr/local/share/ca-certificates/` + `update-ca-certificates` и проверка отпечатка при сборке (не совпал → сборка падает).
   gRPC-клиенту передать системное хранилище (или `GRPC_DEFAULT_SSL_ROOTS_FILE_PATH`), **не** `verify=False`.
3. Сетевой адрес API — только официальный боевой (`invest-public-api.tbank.ru`). Песочница — отдельной настройкой, по умолчанию выкл.

## 3. Загрузка и хранение (SQLite, всё локально)

Команда: `python -m app tinvest-fetch [--months N]`
1. `GetAccounts` → список счетов (тип, статус, имя); фильтр по настройке; закрытые — пропустить.
2. `GetOperationsByCursor` за период, только исполненные (`EXECUTED`), постранично, с ретраями и паузой; лимиты API соблюдать.
3. Инструменты: `figi`/`instrument_uid` → тикер, ISIN, класс, номинал, валюта через сервис инструментов; кэш в SQLite.
4. Таблицы SQLite (миграции через слой `db.py`):
   - `tinvest_operations` — `op_id` (PK, ID брокера), `parent_op_id`, `account_mask`, `date_msk`, `type_api`, `instrument_uid`,
     `ticker`, `isin`, `qty`, `price`, `accrued_int`, `payment`, `commission`, `currency`, `trades_count`, `raw_hash`, `fetched_at`;
   - `tinvest_instruments` — кэш инструментов;
   - `journal_sync` — `op_id`, `status` (`new` | `matched_existing` | `written` | `doubtful` | `unsupported` | `skipped`),
     `journal_id`, `journal_row`, `reason`, `updated_at`.
5. Повторная загрузка того же периода не создаёт дублей (`op_id` — ключ), изменившийся `raw_hash` → в отчёт.

## 4. Сопоставление с «Журналом» (главное — без дублей)

Команда: `python -m app tinvest-sync` (по умолчанию dry-run).
1. Прочитать «Журнал» по заголовкам (строка 4), строки с 5-й до последней непустой «ID».
2. **Уже записанные из API**: в «Источник» есть `T-API <op_id>` → `written`, пропустить.
3. **Совпадение с историей и ручным вводом** (ID `T-ГГГГММДД-…` из отчётов, `M-…` вручную): одна и та же операция, если
   совпадают тип (по таблице §5), бумага (тикер или ISIN), дата (±1 день), количество (если есть) и денежный поток
   (|Δ| ≤ max(1 ₽; 0,5%)). Совпало ровно с одной строкой → `matched_existing` (в лист **ничего не пишем**, чужие строки не трогаем).
   Совпало с несколькими или почти совпало → `doubtful` (в отчёт).
4. Строки `ARCH-…` («Архив: итог»), «Урок», «Правило», «Остаток на начало» — не сделки, в сопоставлении не участвуют.
5. Не сопоставилось → `new`.

## 5. Преобразование операции → строка «Журнала»

Допустимые значения колонки «Операция» — **прочитай из проверки данных колонки D** (data validation) листа, не угадывай.
Предлагаемое соответствие (проверить и уточнить по реальным типам API, итог — в отчёт):

| Тип API (группа) | «Операция» | Кол-во | «Цена / сумма» | НКД | Комиссия |
|---|---|---|---|---|---|
| покупка ценной бумаги | Покупка | шт (не лоты) | цена 1 шт ₽; **облигации — % номинала** | из операции | отдельной суммой из связанной операции комиссии |
| продажа | Продажа | шт | как выше | да | да |
| купон | Купон | — | сумма ₽ после налога | — | — |
| дивиденд | Дивиденд | — | сумма ₽ после налога | — | — |
| погашение | Погашение | шт | 100 | — | — |
| частичное погашение (амортизация) | Амортизация (если есть в списке) | — | сумма ₽ | — | — |
| пополнение / вывод | Ввод / Вывод | — | сумма ₽ | — | — |
| комиссии, налоги, прочее | — | — | — | — | → `unsupported` в отчёт (не пишем в Ф1) |

- Знак денежного потока считает формула листа — код пишет только вводимые колонки (§7).
- Валюта ≠ RUB → `unsupported` в Ф1 (в отчёт), пересчёт курсов — позже.
- Несколько сделок одного поручения → одна строка, «Сделок в строке» = число сделок.
- ID строки: `T-ГГГГММДД-ТИКЕР-ТИП-<6 последних символов op_id>`; «Источник»: `T-API <op_id>`; «Брокер»: `Т`;
  «Статус / примечание»: `импорт API ГГГГ-ММ-ДД`.

## 7. Запись в «Журнал» (`tinvest-sync --apply`)

1. Условия: `--apply` **и** `write.dry_run = нет` **и** нет `doubtful` в этом прогоне (если есть — записать только `new`, `doubtful` оставить в отчёте).
2. **Бэкап перед записью:** сохранить лист «Журнал» целиком (значения **и** формулы, `valueRenderOption=FORMULA`) в
   `/data/backups/journal_ГГГГММДД_ЧЧММ.json` + напомнить в отчёте про историю версий Google. Без бэкапа — не писать.
3. **Куда писать:** первая пустая строка ниже последней непустой «ID» **в зоне, где уже есть формулы** (строки 95–400 по
   SHEETS_INTERFACE изм. v1.26; проверь фактически: в A этой строки должна быть формула/пусто, а не значение).
   Хватает пустых строк с формулами → писать. **Не хватает → стоп, ничего не писать, сообщить** (строки не добавлять).
4. Писать **только** колонки: ID (значение `T-…`), Дата, Брокер, Операция, Тикер / код MOEX, Кол-во, Цена/сумма, НКД,
   Комиссия, Источник, Статус / примечание. Формульные колонки (ISIN, ID идеи, Класс, Денежный поток, Площадка, Сделок…) — не трогать.
5. Один `values.batchUpdate` на прогон, только конкретные ячейки (фильтры скрывают строки — copy/paste не использовать).
6. После записи: перечитать записанные строки, сверить, обновить `journal_sync` (`written`, номер строки); в лог и отчёт.
7. Повторный запуск ничего не дублирует.
