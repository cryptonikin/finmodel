## 1. Принципы (обязательны для кода)

1. **Колонки ищутся по заголовку** (строка 4 рабочих листов, строка 1 «Теги_видео»), не по букве. Совпадение — по началу текста заголовка. Нет заголовка → стоп, без записи.
2. **Ключи строк постоянные:** ID идей `I0xx`, облигаций `B0xx`; тикер — в «Справочнике» (кол. A). Сортировка строк разрешена.
3. **Зоны записи** (цвет = кто пишет):

| Цвет | Кто пишет | Код может писать? |
|---|---|---|
| ярко-жёлтый | владелец, обязательно | никогда |
| светло-жёлтый | владелец, по желанию | никогда |
| серо-голубой | код, если пусто / нет флага «не обновлять»; владелец может править | только по правилам листа |
| серый | формула **или** код (колонки «авто») | только колонки, помеченные «код» ниже |

4. Один писатель на колонку. Переход Apps Script → VPS = смена писателя, колонки те же (§6).
5. Дата + источник у каждого авто-числа (колонки «… на дату», «ФА: источник / статус», «Цена обновлена»).
6. Данные портфеля **никогда** не уходят в LLM. В LLM — только тексты публичных видео и публичные рыночные данные.

## 3. Колонки и писатели

### 3.1 Идеи (заголовки — строка 4)
| Колонка (начало заголовка) | Писатель | Примечание |
|---|---|---|
| ID | Apps Script (новым строкам) | постоянный |
| Инструмент | **владелец** | название из списка / новое → скрипт находит на MOEX |
| Дата идеи | **владелец**; Apps Script 1.47 — сегодня при ручной правке Цели/Стопа/Горизонта/Тезиса/Рисков/сценариев или «Акции» «Лимит позиции вручную» (кроме архивных версий) | дата актуальности; полная переоценка = новая строка; лист сортируется по ней (убыв.) |
| Цель, Стоп, Горизонт, Тип источника, Автор, Тезис, Риски, Ссылка, Откуда, Тренд…, сценарии, P/E, Долг/EBITDA, Дата фунд. | владелец (по желанию) | **кандидаты для автозаполнения из тегов** (§5) |
| Тикер, Статус, Оценка 0–100, Рекомендация, Техника, Фундамент, Видео, Цена сейчас, Вход, Апсайд, Результат, Позиция, Вложено, Получено, Стоимость, Доля, Проверка правил, Дата пересмотра, Дивдох., Класс, Сектор, Валюта, Тип данных | формула | не писать |
| Цена на дату идеи | Apps Script (если пусто) | при пересмотре не меняется — результат с первой даты |
| Версия (авто), Приоритет сортировки (авто) | формула | «архив» = есть более поздняя версия того же тикера |

Правила версий: актуальная строка тикера считает позицию по **всем** версиям тикера; архивная — только по своим сделкам. Журнал привязывает сделку к последней идее с датой ≤ даты сделки. Фильтр-представления: «Актуальные (без архива)», «Все версии по тикеру».

### 3.2 Анализ акций (строка 4; веса — строка 2: ФА I2, ТА K2, Видео M2)
| Колонки | Писатель сейчас | Писатель потом (VPS) |
|---|---|---|
| Тикер | Apps Script `updateAnalysis` (все «Акции» из Справочника) | finmodel |
| Капитализация, SMA50, SMA200, RSI14, ATR14, Макс/Мин 52н, Поддержка/Сопротивление 20д, ТА на дату | Apps Script (свечи MOEX ISS, вс 11:00) | finmodel C2/C3 |
| P/E, P/B, EV/EBITDA, Долг/EBITDA, ROE, Выручка, Чистая прибыль, Период ФА, ФА: источник / статус | Apps Script (smart-lab годовая МСФО CSV), кроме строк с галочкой «Не обновлять ФА» | finmodel C7 |
| Не обновлять ФА, Комментарий | **владелец** | — |
| Название, Сектор, Цена, Тренд, От макс, До поддержки, Дивдох., Видео: …, Апсайд к цели, Баллы, Оценка, Рекомендация, В портфеле | формулы | (позже VPS может писать «Балл …» в лист «Сверка» для сравнения) |

Оценка = взвешенное среднее доступных баллов (ФА 0,4 · ТА 0,3 · Видео 0,3).
Рекомендация модели: в портфеле — «держать» ≥60 / «держать, следить» ≥40 / «сократить?»; вне портфеля — «кандидат на покупку» ≥70 / «наблюдать» ≥50 / «не интересно». Это **расчёт модели**, решение — владельца.

### 3.3 Журнал
Строки 5–94 — история из отчётов (не трогать). С 95-й: владелец вводит Дата, Операция, Инструмент, Кол-во, Цена/сумма (+НКД, комиссия, брокер, источник, примечание); формулы: ID, ISIN, ID идеи, Класс, Денежный поток, Площадка, Сделок. Будущий импорт T-Invest API (VPS) — пишет строки целиком со своим ID `T-…`, дедуп по ID.

### 3.4 Справочник (строка 3 — заголовок, данные с 4-й)
A Тикер (владелец/скрипт) · B–K серо-голубые (скрипт, если пусто) · L Синонимы, AA Рейтинг (владелец) · M–Z серые (скрипт: цены ежедневно, данные по воскресеньям).
**Синонимы (L) — словарь для тегов:** n8n сопоставляет «как назвали в видео» → тикер через A/D/L.

Что должно появиться в промте тегов v3 (для проекта транскрибации):
1. Для каждой упомянутой акции — отдельная строка с **тональностью −2…+2** и **тикером** (список тикеров и синонимов — из «Справочника», передавать в промт как словарь).
2. Числа цели / поддержки / сопротивления — отдельными полями, в ₽, без текста.
3. Типы «уровень» и «цель» — обязательно с числом.
4. Даты — ДД.ММ.ГГГГ; проценты — долями.

**Файлы транскрипций (вход):** `transcripts/ГГГГ-ММ-ДД_Автор_тема.txt`; дата — дата выхода видео (ISO, сортируется); ссылка — первой строкой файла. ## 5. Как теги ложатся в анализ (сейчас формулами, потом кодом)

| Показатель «Анализ акций» | Формула |
|---|---|
| Видео: упоминаний 90д | COUNTIFS(Тикер = X; Дата видео ≥ сегодня−90) |
| Видео: тон | Σ(вес·тон)/Σвес, **вес = 0,5^(возраст, дн / полураспад)**, полураспад — «Скоринг» → «Полураспад веса видео, дней» (45); окно 180 дн |
| Видео: медиана цели | для каждого автора — его **последняя** цель за 180 дн; затем MEDIAN по авторам |
| Апсайд к цели | медиана цели / цена − 1 |
| Видео: последний тезис | самая свежая строка: дата · автор · тезис |
| Балл видео | баллы «Тон видео» и «Апсайд к цели» по порогам листа «Скоринг» (тон +1 = 100, −1 = 0; апсайд 25% = 100, 0% = 0) |

**Перемирие (v1.22):** p = Σ(вес·Значение)/Σвес по тегам «вероятность перемирия»; бета = k·(ралли_бумаги/ралли_IMOEX, дек-24→фев-25) + (1−k)·бета_категории; потенциал = бета × (индекс_мир/IMOEX − 1), [−0,5; 3]; ожид. апсайд = p × потенциал; прогноз t мес = цена × (1 + (1−(1−p)^(t/12)) × потенциал).
**Облигации:** премия = YTM − G(дюрация) (линейно между ОФЗ 1г и 10г); переоценка = p × ModDur × Δставки_мир; балл = взвеш. доходность/рейтинг/сценарий/видео.

Python (VPS) — та же логика: `w = 0.5 ** (age_days / half_life)`; `tone = sum(w*t)/sum(w)` по тегам с тоном за 180 дн; `target = median(last_target_by_author)`.

План (VPS): взвешивать авторов по точности прошлых прогнозов (сверка цели с фактической ценой через N мес) → «рейтинг авторов»; кандидаты в «Идеи» из тегов типа «идея/цель» со статусом «на рассмотрении».

## 6. Переход Apps Script → VPS (пошагово, каждый шаг — тест → подтверждение)

| Шаг | Что | Критерий готовности |
|---|---|---|
| 0 (сейчас) | Пилот: Apps Script пишет ТА/ФА, формулы считают баллы | лист заполняется по вс, ошибок нет 2 недели |
| 1 | n8n пишет теги в «Теги_видео» (dry-run → запись) | ≥ 3 видео, тикеры сопоставлены ≥ 90% |
| 2 | finmodel (Docker) **только читает** листы по этому файлу → отчёт «что вижу» | все заголовки найдены |
| 3 | finmodel считает ТА/ФА и пишет в лист «Сверка» рядом с Apps Script | расхождение SMA/RSI < 1%, P/E совпадает |
| 4 | Смена писателя: в «Анализ акций» ТА/ФА пишет finmodel; в Apps Script отключить `updateAnalysis` (удалить триггер) | 2 недели без расхождений |
| 5 | На VPS: история свечей и МСФО в Postgres, бэктест баллов, рейтинг авторов, импорт T-Invest API в Журнал | по одному модулю |
| 6 | ИИ-комментарий «за/против» по кандидатам (только публичные данные, бесплатная модель) → колонка «Комментарий ИИ» | согласие владельца |

Почему так: таблица остаётся интерфейсом, меняется только «кто пишет»; откат = вернуть триггер Apps Script.

## 7. Риски и ограничения пилота
- smart-lab — сторонний сайт: формат CSV может измениться или доступ закроют → в «ФА: источник / статус» будет «нет данных», старые числа сохраняются; ручная правка + галочка «Не обновлять ФА». Условия использования сайта не проверены — **решение владельца** (альтернатива — ручной ввод или другой источник на VPS).
- Мультипликаторы smart-lab — годовые/LTM, период указан в «Период ФА» (по P/E); банки — без EBITDA.
- Баллы и пороги — **предположение** для старта, калибровать на истории (VPS шаг 5).
- Apps Script: лимит 6 мин на запуск (≈ 60 бумаг ок), UrlFetch ~20 000/день.
